# Intermarket Strategist Mobile

Native Android and iOS application built with Expo / React Native. This is a separate client for the existing Intermarket Strategist Supabase project; it does not replace or modify the production website.

## Implemented foundation

- Cross-platform Android and iOS project structure using Expo SDK 58.
- Shared Supabase authentication with sign-in and account creation.
- Persistent authenticated sessions stored with Android Keystore / iOS Keychain through Expo SecureStore.
- Native member workspace with live notification inbox, published research, trade ideas, and private journal views.
- Premium Lounge text messaging with realtime updates and pinned-message indicators.
- Private analyst/member conversations with realtime text messaging and conversation previews.
- Realtime subscription for newly inserted notifications when Supabase Realtime is available.
- User-owned Expo push-token registry protected by Row Level Security.
- Private-message notification records generated by a database trigger.
- EAS development and internal Android APK build profiles.

## Toolchain

The project targets Expo SDK 58 and React Native 0.88. Install dependencies from this directory with `npm install`, then run `npm run typecheck` and `npx expo-doctor`.

## Local setup

1. Install Node.js 22.13+ or a supported newer even-numbered LTS release.
2. From this directory, run `npm install`.
3. Copy `.env.example` to `.env` and set the existing Supabase project URL and public anon/publishable key. Never put a service-role key in a mobile app.
4. Run `npx expo start` for the UI, or create an EAS development build for native push notification testing.

## Push notification setup

Push delivery requires an Expo/EAS project linked to this app and valid Android/iOS push credentials.

1. Sign in to an Expo account and initialize the EAS project from this directory using `eas init`.
2. Add the resulting EAS project ID to `expo.extra.eas.projectId` in `app.json`.
3. Configure Android FCM v1 credentials and Apple APNs credentials through EAS.
4. Build and install a development APK on a physical Android device (remote push notifications are not supported in Expo Go on Android).
5. Configure an Expo access token as a server-side Supabase secret. It must never be included in the mobile app.
6. Deploy the server-side push function and configure a Supabase Database Webhook for INSERT events on `public.notifications`, targeting that function with JWT verification.
7. Test foreground, background, terminated-app, tap-through, sound, vibration, permission-denied, and token-revocation behavior on physical devices.

The database migration `20261111122514_mobile_push_tokens_and_private_message_notifications.sql` creates the per-device token registry and private direct-message notification trigger. Existing research, trade-publication, and Premium Lounge reply/mention notifications continue to use the existing shared `notifications` table.

## Security and release notes

- Reuse existing Supabase Auth accounts.
- All user data access must remain protected by existing Row Level Security policies.
- Device tokens are scoped to the authenticated user. The client uses only the public Supabase key and the signed-in user's JWT.
- Push delivery must be sent by a trusted server-side Edge Function. Never expose service-role keys or Expo access tokens in the app.
- Push permissions are requested contextually and only after the user understands the benefit.
- Notification sound and vibration remain subject to Android/iOS permission, channel, focus, and silent-mode settings.
- Android test builds can be distributed as APKs. iOS test distribution uses Apple's signed development/TestFlight workflow.
- Do not publish to either app store until both platforms pass real-device testing and the user approves release.
